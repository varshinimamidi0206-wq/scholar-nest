# SCHOLARNEST — FINAL HACKATHON BUILD

Build my complete hackathon project called:

# ScholarNest

### Your Path to the Right Scholarship

Problem Statement:

**E6 — Scholarship Discovery Platform**

Requirement:

Create a system that recommends scholarships to students based on academic performance, income category, course, location, and eligibility.

This must be a serious, polished, production-style full-stack hackathon project — NOT a simple scholarship listing website.

The core product idea is:

> **ScholarNest helps students discover scholarships they are eligible for, understand why they qualify, prepare the required documents, and track their applications from discovery to submission.**

The product should feel like a real startup product that could be used by students across India.

# 1. CRITICAL RULES

Follow these rules throughout development.

### DO

* Build a real working full-stack application.
* Use a real PostgreSQL database.
* Use real authentication.
* Use bcrypt for password hashing.
* Use JWT authentication.
* Protect private API routes.
* Implement real CRUD.
* Persist user data.
* Implement user-level data isolation.
* Validate backend inputs using Zod.
* Use proper HTTP status codes.
* Use centralized error handling.
* Use Gemini only from the backend.
* Keep API keys in environment variables.
* Use structured JSON for Gemini responses.
* Make the application responsive.
* Create loading, error, empty, and success states.

* Keep code clean and modular.
* Reuse existing working code if it already exists.

### DO NOT

* Do not create a fake frontend with hardcoded dashboard data.
* Do not use fake authentication.
* Do not store passwords in plain text.
* Do not expose Gemini API keys.

* Do not put secrets in GitHub.
* Do not use Gemini for deterministic scholarship filtering.
* Do not generate fake scholarship statistics.
* Do not fabricate official scholarship URLs.
* Do not claim AI legally verifies government documents.
* Do not repeatedly regenerate the entire application.
* Do not delete working functionality unnecessarily.
* Do not install unnecessary packages.
* Do not create unnecessary animations.
* Do not make the project just a chatbot.

The scholarship matching workflow must remain the heart of the product.

# 19. STRUCTURED GEMINI RESPONSE

Use structured JSON.

Example:

```json

  "reasons": [
    "Your CGPA meets the academic requirement.",

  ],
  "missingRequirements": [],
  "nextSteps": [
    "Prepare your income certificate.",
    "Verify your latest academic document.",
    "Apply through the official scholarship portal."
  ]
}
```

Validate the response using Zod.

If Gemini returns invalid data:

* catch the error
* do not crash the server
* provide a safe fallback

Cache repeated AI outputs using the `ai_outputs` table where appropriate.
